# Witnesses

This directory holds curated, versioned scientific results. It is released under
CC0 1.0 Universal ([LICENSE](LICENSE)); the rest of the repository is
dual-licensed MIT OR Apache-2.0.

For integers `k >= 2` and `n >= 1`, the power-sum graph `G_k(n)` has vertex set
`{1, ..., n}` and joins two distinct vertices whose sum is a perfect `k`-th
power. `n_min(k)` denotes the least `n` for which `G_k(n)` has a Hamiltonian
cycle.

|---|---|---|---|---|
| 2 | 32 | — | classical | not included; see below |
| 3 | **473** | `9^3 - 8^3/2` | G. Resta, c. 2005 | [`k3-n473/`](k3-n473/) |
| 4 | **9641** | `11^4 - 10^4/2` | R. Tauraso, 2006 | [`k4-n9641/`](k4-n9641/) |

| 6 | **15748961** | `17^6 - 16^6/2` | this project | [`k6-n15748961/`](k6-n15748961/) |
| 7 | `>= 587761723` | `19^7 - 18^7/2` | — | no witness yet; lower bound in [`k7-n587761723/`](k7-n587761723/) |

[`k5-n490463/`](k5-n490463/) holds an earlier, non-minimal witness for `k = 5`.
It remains valid and independently verified, and records how the search
progressed.

[`k3-n473-800/`](k3-n473-800/) holds one Hamiltonian cycle of `G_3(n)` for
every `n` from 473 to 800, evidence for the conjecture that every admissible
`n` is Hamiltonian for `k >= 3`.

[`k4-n18193/`](k4-n18193/) holds a Hamiltonian cycle of `G_4(18193)`, the
first value of the `k = 4` mainland: with the island bundle of
power-sum-graphs 1.0.0, it shows that Hamiltonicity is not monotone in `n`.

[`k6-n30039769/`](k6-n30039769/) holds a Hamiltonian cycle of `G_6(30039769)`,
the first value of the `k = 6` mainland, in the bases encoding.
[`k6-n16777215/`](k6-n16777215/) holds one of `G_6(16777215)`, the last value of
the `k = 6` island and the hardest graph met so far, found with a motif
imposed (see [`../doc/en/end-of-island.md`](../doc/en/end-of-island.md)). See
[`../doc/en/continent.md`](../doc/en/continent.md) for the other runs on the mainland.

For `k = 2` the answer is the classical square-sum problem and is already known;
see OEIS [A071984](https://oeis.org/A071984) and
[A272259](https://oeis.org/A272259), whose rows start at `n = 32`.

The sequence `n_min(k)` is OEIS [A115418](https://oeis.org/A115418), submitted by Roberto Tauraso in 2006
with the terms 2, 32, 473, 9641. The cubic loop of length 473 is due to Giovanni
Resta, who reduced the search to a travelling salesman problem (Carlos Rivera,
[Puzzle 311](http://www.primepuzzles.net/puzzles/puzz_311.htm): Sum to a cube). No published proof that 473 and 9641 are minimal has been
found; the `k3` and `k4` bundles supply one. `246877` and `15748961` extend the
sequence and are, as far as is known, new.

## What a bundle contains

A bundle claiming a minimal `n` carries **both halves** of the statement.

**Existence** is `cycle.txt`, a plain list of the integers `1..n` in cyclic
order. It is exported canonically: rotated so vertex `1` is first, oriented so
the smaller neighbour of `1` is second.

**Lower bound** is `bands.txt`, the `pc-scan --bands` output over `1..n-1`. It
splits every smaller value into bands, each naming a vertex of degree at most
one — which no Hamiltonian cycle can use — throughout its range. A dozen lines
cover millions of values, because the degree of a vertex never decreases as `n`
grows: equal at both ends of a band means equal throughout.

Up to version 0.1.0 the lower bound was `scan.txt`, one line per `n`. It grew
linearly with `n` — 33 GB at `k = 7` — and remains at the `witness-k*` tags.

`final.pcdump.json` is provenance only. The mathematical certificate is the
plain cycle.

Each artifact is stored compressed next to the SHA-256 of its **uncompressed**
form, so the checksum identifies the mathematical content rather than a
particular compression.

## The lower bound

Vertex `v` is adjacent to `p - v` exactly when `p` is a perfect `k`-th power with
`v + 1 <= p <= v + n` and `p != 2v`, the excluded case being a self-loop.
Counting those powers gives the degree of `v` directly, with no graph.

The binding vertices are the self-loop positions themselves. For even `m`, the
vertex `v = m^k/2` lies inside the interval generated by `m^k` but cannot use it,
so it needs the next power `(m+1)^k` to enter its window:

| k | binding vertex | needs |
|---|---|---|
| 3 | `256 = 8^3/2` | `9^3 = 729` |
| 4 | `5000 = 10^4/2` | `11^4 = 14641` |
| 5 | `124416 = 12^5/2` | `13^5 = 371293` |
| 6 | `8388608 = 16^6/2` | `17^6 = 24137569` |
| 7 | `306110016 = 18^7/2` | `19^7 = 893871739` |

This condition is **necessary, not sufficient**. `k = 2` is the counterexample to
keep in mind: the analogous bound is `31`, and `G_2(31)` passes every necessary
condition implemented in `pc-scan`, yet the true minimum is `32`.

For `k = 3, 4, 5, 6` the two halves meet, because a witness exists at the very
first `n` the bound allows. That is what makes those values theorems rather than
bounds. For `k >= 7` only the lower bound is established.

See [`k5-n246877/README.md`](k5-n246877/README.md) for the full discussion.

## Verifying any bundle

From the repository root, with `K` and `N` set to the bundle's parameters:

```console
xz -dc witness/k$K-n$N/cycle.txt.xz > /tmp/powercycle-cycle.txt
sha256sum /tmp/powercycle-cycle.txt          # must match cycle.txt.sha256

cargo run --release --manifest-path src/verify/rust/Cargo.toml \
  -- $K $N /tmp/powercycle-cycle.txt

python src/verify/python/verify-cycle.py $K $N /tmp/powercycle-cycle.txt
```

Both verifiers live outside the powercycle dependency graph. They take only `k`,
`n` and a candidate list, and check that it is a permutation of `1..n` whose
consecutive sums, closure included, are perfect `k`-th powers. Neither reads a
dump, an edge ID, a patch history or anything from the solver.

For a bundle that claims minimality, the lower bound:

```console
xz -dc witness/k$K-n$N/bands.txt.xz > /tmp/powercycle-bands.txt
sha256sum /tmp/powercycle-bands.txt          # must match bands.txt.sha256

cargo run --release --manifest-path src/verify/rust/Cargo.toml \
  --bin powercycle-verify-bands -- $K $N /tmp/powercycle-bands.txt

python src/verify/python/verify-bands.py $K $N /tmp/powercycle-bands.txt
```

These two check that the bands cover `1..n-1` without gap and, at both ends of
each band, recount the powers in the window of its vertex to confirm the claimed
degree. Like the cycle verifiers, they use only `k`, `n` and the file.
