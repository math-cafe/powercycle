# Witnesses

This directory holds curated, versioned scientific results. It is released under
CC0 1.0 Universal ([LICENSE](LICENSE)); the rest of the repository is
dual-licensed MIT OR Apache-2.0.

For integers `k >= 2` and `n >= 1`, the power-sum graph `G_k(n)` has vertex set
`{1, ..., n}` and joins two distinct vertices whose sum is a perfect `k`-th
power. `n_min(k)` denotes the least `n` for which `G_k(n)` has a Hamiltonian
cycle.

It remains valid and independently verified, and records how the search
progressed.

For `k = 2` the answer is the classical square-sum problem and is already known;
see OEIS [A272259](https://oeis.org/A272259), whose rows start at `n = 32`.

## What a bundle contains

A bundle claiming a minimal `n` carries **both halves** of the statement.

**Existence** is `cycle.txt`, a plain list of the integers `1..n` in cyclic
order. It is exported canonically: rotated so vertex `1` is first, oriented so
the smaller neighbour of `1` is second.

**Lower bound** is `scan.txt`, the `pc-scan` output over `1..n`. It records, for
every smaller value, a vertex of degree at most one — which no Hamiltonian cycle
can use.

`final.pcdump.json` is provenance only. The mathematical certificate is the
plain cycle.

Each artifact is stored compressed next to the SHA-256 of its **uncompressed**
form, so the checksum identifies the mathematical content rather than a
particular compression.

## The lower bound

Vertex `v` is adjacent to `p - v` exactly when `p` is a perfect `k`-th power with
`v + 1 <= p <= v + n` and `p != 2v`, the excluded case being a self-loop.
Counting those powers gives the degree of `v` directly, with no graph.

The binding vertices are the self-loop positions themselves. For even `m`, the
vertex `v = m^k/2` lies inside the interval generated by `m^k` but cannot use it,
so it needs the next power `(m+1)^k` to enter its window:

| k | binding vertex | needs |
|---|---|---|
| 3 | `256 = 8^3/2` | `9^3 = 729` |
| 4 | `5000 = 10^4/2` | `11^4 = 14641` |
| 5 | `124416 = 12^5/2` | `13^5 = 371293` |
| 6 | `8388608 = 16^6/2` | `17^6 = 24137569` |
| 7 | `306110016 = 18^7/2` | `19^7 = 893871739` |

This condition is **necessary, not sufficient**. `k = 2` is the counterexample to
keep in mind: the analogous bound is `31`, and `G_2(31)` passes every necessary
condition implemented in `pc-scan`, yet the true minimum is `32`.

For `k = 3, 4, 5` the two halves meet, because a witness exists at the very first
`n` the bound allows. That is what makes those values theorems rather than
bounds. For `k >= 6` only the lower bound is established.

See [`k5-n246877/README.md`](k5-n246877/README.md) for the full discussion.

## Verifying any bundle

From the repository root, with `K` and `N` set to the bundle's parameters:

```console
zstd -dc witness/k$K-n$N/cycle.txt.zst > /tmp/powercycle-cycle.txt
sha256sum /tmp/powercycle-cycle.txt          # must match cycle.txt.sha256

cargo run --release --manifest-path src/verify/rust/Cargo.toml \
  -- $K $N /tmp/powercycle-cycle.txt

python src/verify/python/verify-cycle.py $K $N /tmp/powercycle-cycle.txt
```

Both verifiers live outside the powercycle dependency graph. They take only `k`,
`n` and a candidate list, and check that it is a permutation of `1..n` whose
consecutive sums, closure included, are perfect `k`-th powers. Neither reads a
dump, an edge ID, a patch history or anything from the solver.
