# Powercycle witness: k = 5, n = 246877

This directory contains the curated **minimal** Hamiltonian-cycle witness for the
power-sum graph `G_5(246877)`.

## Mathematical statement

The graph has vertex set `1, 2, ..., 246877`. Two distinct vertices `a` and `b`
are adjacent exactly when `a + b` is a perfect fifth power.

The file `cycle.txt.xz` contains a Hamiltonian cycle: after decompression it is a
plain-text file with one vertex per line. Every integer from `1` through `246877`
appears exactly once, and every consecutive pair, including the closing pair from
the last line back to the first, has a sum equal to a perfect fifth power.

## Minimality

This bundle carries both halves of the statement

```text
n_min(5) = 246877
```

that is, `246877` is the least `n` for which `G_5(n)` has a Hamiltonian cycle.

**Existence.** `cycle.txt` is a Hamiltonian cycle of `G_5(246877)`.

**Lower bound.** For every `n` in `[1, 246876]` the graph `G_5(n)` contains a
vertex of degree at most one. A Hamiltonian cycle uses exactly two edges at every
vertex, so no such `n` admits one. `bands.txt` records this vertex for each `n`.

The obstruction is elementary and does not depend on any search. Vertex `v` is
adjacent to `p - v` exactly when `p` is a perfect fifth power with
`v + 1 <= p <= v + n` and `p != 2v`, the excluded case being the self-loop.
Counting those powers gives the degree of `v` directly.

The binding vertex just below the threshold is

```text
v = 124416 = 12^5 / 2
```

It lies inside the interval generated by `12^5 = 248832` but cannot use that
power, because `124416 + 124416` is a self-loop rather than an edge. Its only
other power is `11^5 = 161051`, so it has degree one until `13^5 = 371293` enters
its window, which happens exactly at

```text
n = 13^5 - 12^5 / 2 = 371293 - 124416 = 246877
```

### What the lower bound does not say

The degree condition is **necessary, not sufficient**. Passing it does not imply
that a Hamiltonian cycle exists, so the same argument cannot by itself determine
`n_min` for other exponents.

The square-sum case is the counterexample to keep in mind: for `k = 2` the
analogous degree bound is `31`, and `G_2(31)` passes every necessary condition
implemented in `pc-scan`, yet the least `n` with a Hamiltonian cycle is `32`.

Here the two halves happen to meet, because a witness exists at the first `n` the
degree bound allows. That coincidence is what makes `n_min(5) = 246877` a
theorem rather than a bound.

## Prior work

`n_min(5) = 246877` is, as far as is known, new. It extends OEIS [A115418](https://oeis.org/A115418), which
lists `n_min(k)` for `k = 1 .. 4` (Roberto Tauraso, 2006; the cubic case is due
to Giovanni Resta).

## Canonical witness identity

The uncompressed `cycle.txt` has SHA-256:

`8988c848256b7227d95e7501c517700a4970fc67fb79151e178ebc5bd630fc3b`

The cycle is exported canonically by rotating it so that vertex `1` is first and
choosing the orientation for which the smaller of the two neighbours of `1` is
second. It begins `1, 31, 212, ...` and ends at `242`, closing with
`242 + 1 = 243 = 3^5`.

`cycle.txt.sha256` stores the checksum of the **uncompressed** witness.

## Lower-bound certificate

The uncompressed `bands.txt` has SHA-256:

`42c068574e3e1b833ff8244c8ba93cca1e556217566acaa3bcb036bdeed7a65d`

It is the `pc-scan --bands` output for `n = 1 .. 246876`: 12 tab-separated
lines, each a range of `n` with the offending vertex and its degree. The degree
of a vertex never decreases as `n` grows, since its window only widens, so a
band that holds at both ends holds throughout. Checking each band at its two
endpoints therefore settles every `n` below the threshold, and the file
contains the whole lower-bound argument.

Every rejection in the range comes from the graph-free degree check, so no graph
is built while reproducing it.

Up to version 0.1.0 the bundle carried `scan.txt` instead, one line per `n`,
still available at the tag `witness-k5-n246877`.

## Provenance

The final versioned powercycle dump is stored as `final.pcdump.json.xz`. Its
semantic dump ID is:

`110da2ad0fd9…`

The successful chain for this witness was:

- SAT tour 1 produced a raw 2-factor with 8 cycles, giant size 182200 and
  residual 64677.
- SAT tour 2, after one round of budgeted boundary subtour-elimination cuts,
  produced a raw 2-factor with 5 cycles, giant size 106589 and residual 140288.
- Two greedy `three-opt-111` moves closed it into a single cycle of length
  246877. No `2+1` move and no alternating repair were needed.

Total search time was 4.4 seconds.

The final dump is a provenance artifact. The mathematical certificate is the
plain cycle witness itself.

## Independent verification

The repository contains two independent witness verifiers:

- a standalone Rust verifier under `src/verify/rust/`;
- a Python standard-library-only verifier under `src/verify/python/`.

They verify only the witness definition: permutation of `1..n` and the fifth-power
condition on every consecutive sum, including closure. They do not use the SAT
solver, dump format, graph edge IDs, patch history or search implementation.

Typical checks from the repository root are:

```console
xz -dc witness/k5-n246877/cycle.txt.xz > /tmp/powercycle-cycle.txt

sha256sum /tmp/powercycle-cycle.txt

cargo run --release \
  --manifest-path src/verify/rust/Cargo.toml \
  -- 5 246877 /tmp/powercycle-cycle.txt

python src/verify/python/verify-cycle.py \
  5 246877 /tmp/powercycle-cycle.txt
```

The lower bound is checked by two independent verifiers of the same kind, then
replayed:

```console
xz -dc witness/k5-n246877/bands.txt.xz > /tmp/powercycle-bands.txt

sha256sum /tmp/powercycle-bands.txt

cargo run --release \
  --manifest-path src/verify/rust/Cargo.toml \
  --bin powercycle-verify-bands -- 5 246877 /tmp/powercycle-bands.txt

python src/verify/python/verify-bands.py \
  5 246877 /tmp/powercycle-bands.txt

cargo run --release --bin pc-scan -- --bands --quick-only 5 1 246876 \
  | diff - /tmp/powercycle-bands.txt
```

The SHA-256 values reported by the checksum commands must match the ones given
above.
