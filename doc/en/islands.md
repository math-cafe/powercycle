# Admissible islands

For `k >= 2` and `n >= 2`, the power-sum graph `G_k(n)` has vertex set
`{1, ..., n}` and joins two distinct vertices whose sum is a perfect `k`-th
power. A Hamiltonian cycle uses exactly two edges at every vertex, so

```text
G_k(n) Hamiltonian  =>  delta(G_k(n)) >= 2
```

This document characterises the set that condition allows:

```text
I_k = { n : delta(G_k(n)) >= 2 }
```

Its connected components in the integers are the **admissible islands**. Every
`n` outside `I_k` is settled: no Hamiltonian cycle, by an argument short enough
to check by hand.

---

## 1. The threshold of a vertex

Vertex `x` is adjacent to `p - x` exactly when `p` is a perfect `k`-th power
with

```text
x + 1 <= p <= x + n        and        p != 2x
```

the excluded case being `x + x = p`, a self-loop rather than an edge. Ordering
the true neighbours of `x` as `y_1 < y_2 < ...`, the vertex reaches degree two
exactly when `n` is large enough to contain both `x` itself and `y_2`:

```text
tau_k(x) = max(x, y_2(x))

d(x) >= 2   in G_k(n)   <=>   n >= tau_k(x)
```

Since every `x <= n` must clear its own threshold, and `tau_k(n) >= n` always,

```text
delta(G_k(n)) >= 2   <=>   max over x <= n of tau_k(x)  =  n
```

A vertex with `tau_k(x) > x` therefore forbids the whole band
`[x, tau_k(x) - 1]`: once it enters the graph, the graph stays deficient until
its second neighbour arrives. `I_k` is the complement of the union of those
bands.

**A single vertex's threshold is not the start of an island.** Before one band
closes, a later vertex can open a longer one. That is exactly what happens at
`k = 6` around 7 625 857, and it is the mistake an earlier draft of this
analysis made.

---

## 2. Computing it in O(k)

The bands need not be enumerated one vertex at a time.

**Segmentation.** Between two consecutive events — a power `a^k`, or a
loop position `a^k / 2` for even `a` — the two lowest powers above `x` are
fixed. On such a segment `tau_k(x) = max(x, p_2 - x)`.

**Nesting.** The obstruction of `x` is `[x, p_2 - x - 1]`. As `x` grows its
left end rises and its right end falls, so the obstructions within a segment
are nested. **Only the segment's left endpoint contributes.**

**Termination.** Once `(a+3)^k <= 2 a^k`, three powers always lie in `(x, 2x]`,
so discarding the possible self-loop still leaves two neighbours. No new
obstruction can appear beyond the safe base

```text
a* = ceil( 3 / (2^(1/k) - 1) )  ~  4.33 k
```

which is about fifty segments at `k = 12`. The last island is therefore always
unbounded.

The whole computation is `O(k log k)` and **independent of n**: all islands for
`k = 2..16` take a couple of milliseconds. Scanning `n` one value at a time
took 24 seconds for `k = 6` alone, and is simply impossible from `k = 7` on,
where the first island starts at 5.9 x 10^8.

## 4. Where each island begins

Every first candidate in the table equals `(m+1)^k - m^k / 2` for an even `m`,
and the binding vertex just below it is the self-loop position `m^k / 2`: it
lies inside the interval generated by `m^k` but cannot use it, so it waits for
the next power.

| k | binding vertex | waits for | first candidate |
|---|---|---|---|
| 2 | `18 = 6^2/2` | `7^2` | 31 |
| 3 | `256 = 8^3/2` | `9^3` | 473 |
| 4 | `5000 = 10^4/2` | `11^4` | 9 641 |
| 5 | `124416 = 12^5/2` | `13^5` | 246 877 |
| 6 | `8388608 = 16^6/2` | `17^6` | 15 748 961 |
| 7 | `306110016 = 18^7/2` | `19^7` | 587 761 723 |

`m = 2k + 2` for `k = 2..5`, then `2k + 4` for `k = 6..9`, then `2k + 6` for
`k = 10..12`. The jumps are why no single closed form covers every `k`: at
`k = 6` the candidate from `m = 14` would be 7 625 857, but `14^6 = 7529536`
is below it, and the vertices from there up hold only `15^6` in their window.
That island is a phantom.

Two further conditions decide the shape of an island, both verified against
the measured intervals for every case in the table:

```text
the island from q exists          <=>   (1 + 1/q)^k < 3/2
it is bounded above at q^k - 1    <=>   (1 + 2/q)^k > 2
```

---

## 5. What this does and does not prove

`n` outside `I_k` is proof of non-Hamiltonicity, and the certificate is four
integers: the interval, the offending vertex, and the two powers bracketing its
window.

`n` inside `I_k` proves nothing. The degree condition is necessary, never
sufficient. **`k = 2` is the standing counterexample**: `I_2` starts at 31, and
`G_2(31)` has minimum degree two, is 1-tough as far as any search has gone, and
is still not Hamiltonian — see [`non-hamiltonicity.md`](non-hamiltonicity.md).
The true minimum is 32.

For `k = 3, 4, 5` the two halves meet, because a witness exists at the very
first admissible `n`. That coincidence is what makes those values theorems
rather than bounds. For `k >= 6` only the lower bound is established.

## 6. Verification

The table has three independent derivations that agree:

1. **`pc-scan --quick-only`**, the repository's sweep over events, run over the
   full range for `k <= 6` and at every island boundary up to `k = 12` — 24
   boundary checks, all matching;
2. **a re-derivation from the definition**, written separately, sweeping the
   same intervals but from the degree formula rather than the band structure;
3. **a brute-force count** for `k = 5`, walking every vertex of every `n` below
   246 877 with a per-vertex power count. It confirmed all 246 876 values and
   took hours, but shares no logic with the other two.

The first two both use an event sweep and could in principle share a mistake;
the third cannot. That is why it was worth running.
